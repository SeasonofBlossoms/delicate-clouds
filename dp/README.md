让团队成员能够开发和使用基于部门组件库的模板。

步骤：

1. 理解当前 CLI 工具的结构和模板系统。
   cli/README.md
2. 部门项目各个模块页面布局和使用组件方式。
3. 调查部门组件库的使用方式和可扩展性。
4. 与 UI 团队沟通，确定设计规范、组件使用规范等。
   ./UI_STEP.md
5. 确定模板开发规范，包括模板结构、可配置项等。
   ./TENOLATE_STEP.md
6. 提供模板开发文档和示例。

具体行动：

1. 分析现有模板系统：项目中与模板相关的文件，文件作用。
2. 确定模板开发规范：
   1. 模板应该包含哪些文件？例如：组件、页面、路由、状态管理、API 等。
   2. 模板的配置文件（如 项目 package.json、配置文件、组件 hook、组件可选参数）如何生成？
   3. 模板变量如何替换？例如模板生成后需要插入 cli 版本、作者等。
3. 与 UI 团队沟通：
   1. 了解设计规范：颜色、字体、间距、组件样式等。
   2. 了解组件库的使用规范：哪些组件常用，有哪些自定义的组件，组件的默认配置是什么。
   3. 确定模板中需要使用的 UI 组件和布局。
4. 调查部门组件库：
   1. 组件库的安装和引入方式。
   2. 组件库的版本管理。
   3. 组件库的按需引入配置（二次封装暂不支持）。
   4. 组件库的定制化能力（主题、样式等）（未实现）。
5. 提供模板开发文档：

入手点：

1. 先熟悉现有模板的结构和生成方式。
2. 与 UI 团队和组件库维护团队开会，明确规范。
3. 创建一个基于部门组件库的模板示例，并编写文档。

具体操作：

1. 创建一个新的模板，例如 `templates/elementplus-app`。
2. 在该模板中，使用部门封装的 ElementPlus 组件。
3. 编写对应的生成器，例如 `src/templates/generators/elementplus-generator.js`。
4. 在生成器中处理依赖安装（包括部门组件库）。
5. 编写模板配置文件，例如模板的 package.json 中依赖部门组件库。
6. 测试模板生成的项目是否能正常运行。

与 UI 沟通的内容：

1. 设计规范：
   - 色彩体系
   - 字体体系
   - 图标库
   - 布局规范
   - 组件使用规范（例如按钮的大小、类型等）
2. 模板类型：
   - 需要开发哪些类型的模板？例如后台管理系统、前端网站等。
   - 每种模板的典型页面有哪些？例如登录页、列表页、表单页等。
3. 组件库使用：
   - 组件库的版本
   - 组件库的全局配置
   - 组件库的按需引入方式
   - 组件库的样式覆盖方法

调查事项：

1. 部门组件库的 npm 包名、版本、安装方式。
2. 组件库的文档和示例。
3. 组件库的更新频率和版本策略。

总结：

我们需要从技术和设计两个角度入手，确保模板既符合设计规范，又能通过 CLI 工具快速生成。同时，要制定模板开发规范，方便团队成员参与开发。

接下来，我们可以先创建一个基于部门组件库的模板示例，然后与 UI 团队评审，再逐步完善。
